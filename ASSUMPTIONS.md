# Assumptions

| ID | Assumption | Why I needed it | Impact if it is wrong |
|---|---|---|---|
| AS-01 | The five Home Essentials answers can be mapped to bands (for example, postal code → rating zone, versioned in Salesforce), so each country has a finite answer space that can be rated in a daily batch | Quoting from a pre-computed grid is how quotes stay available while the org is down (≈ 97%, `SALESFORCE_CONSTRAINTS.md:15`) against the 99.5% target (C1) | No grid: quotes use live rating, quote availability is capped near 97% and ADR-0002 declares the C1 gap |
| AS-02 | The Salesforce platform team can compute the grid inside each org after the 05:00 UTC publication and expose it through the System API in a few bulk calls, with Q1 effort that fits next to configuring the product in three orgs. To be confirmed in a December spike, with an answer before 15 Dec 2026 | A grid built by the cell with one REST call per combination is bounded by the 40 req/s limit and the daily budget (`SALESFORCE_CONSTRAINTS.md:19,31,35`) | Plan B: the cell builds the grid over REST, capped at 10,000 combinations per country (10,000 ÷ 10 req/s ≈ 17 min; 10,000 ÷ 250,000 = 4% of the MX channel budget). If the answer space is larger, live rating becomes the main path |
| AS-03 | The data that issuance needs (country-specific documents and consents, `SALESFORCE_CONSTRAINTS.md:8`) can be validated through the System API before payment while the org is up, so issuance failures after payment are rare | Purchase in the same session (BR-01) charges the customer before the policy is issued | More cases reach the manual exception queue (refund or manual issuance); the 3-minute issuance target is missed more often |
